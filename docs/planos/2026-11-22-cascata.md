# Cascata e regra de decisão — plano de implementação (etapa 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** dividir os dados sem vazamento, treinar e calibrar a cascata (regressão logística e Random Forest), comparar os dois na validação e oferecer um comando que verifica páginas com o detector salvo.

**Architecture:** `mhf/divisao.py` (grupos e conjuntos), `mhf/metricas.py` (métricas com pesos), `mhf/cascata.py` (características, modelos, cascata vetorizada e `Detector` para uma página). Três scripts finos: `dividir.py`, `treinar.py`, `verificar.py`. A cascata é uma função só (`aplicar_cascata`), usada pelo treino e pelo `Detector`.

**Tech Stack:** Python 3.13, numpy, scikit-learn 1.9.1 (`StratifiedGroupKFold`, `LogisticRegression`, `RandomForestClassifier`, `roc_auc_score`), joblib, unittest.

**Spec:** `docs/especificacoes/2026-11-22-cascata.md`

## Global Constraints

- Nenhuma escolha olha o conjunto de teste; o `verificar.py` só lê o teste com `--usar-teste`.
- s útil = amostra com s e `elementos > 5` (`ELEMENTOS_MIN_S = 6`); senão `s_ausente = 1` e as características de s valem 0.
- Exclusões em `config/exclusoes.json`: Phish360 `trainval\P10255_caixa`, `trainval\P10310_caixa`, `trainval\P10322_caixa`, `trainval\P10339_caixa`, `trainval\P10345_caixa` (CaixaBank).
- Sementes: `random_state=0` em todas as divisões e no Random Forest.
- Divisão: grupos por hash canônico; teste = dobras 0, 1, 2 de `StratifiedGroupKFold(10)` nos grupos só do Phishpedia; CV = `StratifiedGroupKFold(5)` no desenvolvimento.
- θ_h = percentil 99 de d₁ dos phishings de 𝒯 do desenvolvimento; τ = menor limiar com FPR ≤ 1% nas páginas legítimas do desenvolvimento (escores fora da dobra, por amostra).
- Rótulos de veredito: `"phishing"` / `"legitima"`; motivos: `sem_template_proximo`, `dominio_legitimo_estagio1`, `abaixo_do_limiar`, `dominio_legitimo_estagio2`, `phishing`.
- Commits só de código sem trailer; commits com documentação com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

3. Amostra sem s ou com DOM degenerado: `s_ausente = 1`, s zerado, e a mesma regra no `Detector` e na tabela. Teste na Task 3.
4. `Detector.decidir` sobre φ de uma amostra dá o mesmo veredito que `aplicar_cascata` sobre a linha da tabela da mesma amostra. Teste na Task 5.
5. Benign sem URL: o id (nome da pasta) é usado como host na checagem de domínio. Teste na Task 4.

### Task 2: métricas

**Files:** Create `src/mhf/metricas.py`, `tests/test_metricas.py`.

**Interfaces — produz:**
- `binarias(real, previsto, pesos=None) -> dict`: `vp, fp, vn, fn, precisao, revocacao, f1, especificidade, fpr, acuracia` (pesos somados; divisão por zero → NaN).
- `auc(real, escores, pesos=None) -> float` (NaN com uma classe só).
- `top1(real, previsto, pesos=None) -> float`.
- `limiar_para_fpr(escores_neg, pesos_neg, peso_total_neg, alvo) -> float`: menor τ tal que o peso dos negativos com escore ≥ τ, dividido por `peso_total_neg`, fique ≤ alvo. Negativos ausentes da lista (liberados antes do limiar) contam só no total.
- `limiar_f1(escores, positivo, pesos, peso_total_pos) -> float`: τ que maximiza o F1 entre os candidatos.
